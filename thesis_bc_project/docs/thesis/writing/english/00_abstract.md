# Abstract

Betweenness Centrality (BC) measures how often a vertex lies on shortest paths between other vertex pairs. Exact all-sources BC repeatedly performs Breadth-First Search (BFS) and reverse dependency accumulation from every source, making it computationally expensive. GPUs offer substantial parallelism, but irregular frontiers and degree distributions create workload imbalance. Source batching increases parallelism while increasing the batch-dependent working set of source-local state, which pressures finite GPU memory.

This thesis designs and evaluates a batch-based GPU execution framework for exact BC on undirected, unweighted graphs using an NVIDIA GH200. The framework integrates block-based source assignment, Hybrid BFS, Warp-Cooperative Accumulation, and Dual-Stream Execution. GPU_Opt, GPU_Opt_Pure (Pure), and GPU_Opt_Pure_Chunked (Chunked) are memory-management variants of this framework, using Unified Memory (UM), device-only memory, and source sub-batching, respectively.

On one GH200, block-based GPU_Opt with a fixed batch size of 512 was 1.31–3.17× faster in median-to-median comparisons than a graph-wise tuned third-party PathMerge snapshot on email-EuAll and roadNet-PA/TX/CA. The individual speedups were 3.17×, 1.31×, 1.51×, and 1.45×, respectively. Factorial ablation showed substantial observed effects from Hybrid BFS and Dual-Stream Execution, whereas the effect of Warp-Cooperative Accumulation was graph-dependent; these observations do not establish independent causal contributions.

On the corrected 325557 input, Pure succeeded at b4096 and failed at b8192 with a CUDA device-memory out-of-memory error. UM succeeded at b10240 and failed at b12288 under the host-memory cgroup limit. Chunked controlled the resident working set through source sub-batching and succeeded at the tested upper bound, b16384. The capacity pressure concerned source-local state rather than the graph file. Tier A comprised three full-vector independent-reference comparisons, while Tier B comprised ten inter-implementation comparisons on the corrected input. All 13 passed the predefined mixed tolerance with zero missing indices and zero tolerance-violating mismatches, but none was byte-identical; Tier B was not independent-reference validation.

Within the evaluated RQ1 scope, the integrated framework improved performance and provided different feasible batch ranges through its memory variants. It also supported systematic evaluation of performance, components, capacity, and numerical behavior. The results are limited to one GH200, the evaluated graphs, and the retained third-party PathMerge snapshot as an external comparator; they do not generalize to PathMerge overall. UM and Chunked do not provide unlimited capacity, and memory feasibility alone does not establish a performance ranking.

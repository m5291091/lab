# グラフデータセット

このディレクトリには、NVIDIA GH200 Grace Hopper Superchip（Miyabi-G スーパーコンピュータ）上での
Betweenness Centrality (BC) 実験に使用するすべてのグラフデータセットが格納されています。

すべてのグラフは **CSR (Compressed Sparse Row)** テキスト形式で保存されています。
これは GPU コンピューティングにおけるスパースグラフの標準的な表現形式です。

## 📖 前提知識

この節では、グラフ理論や BC を全く知らない方のために、最低限の用語を説明します。

### グラフとは？

「グラフ」とは、**モノ（頂点/ノード）** と **つながり（辺/エッジ）** の集まりです。

```
例：SNS の友達関係

  田中 ── 鈴木
   |        |
  佐藤 ── 山田

  ・人（田中、鈴木…）→ 頂点（ノード）
  ・友達関係（──）→ 辺（エッジ）
```

日常生活のさまざまなものがグラフで表せます：
- 🧑‍🤝‍🧑 **人と人のつながり** → SNS の友達関係、メールのやり取り
- 🌐 **Web ページとリンク** → あるページから別のページへのリンク
- 🛣️ **場所と道路** → 交差点（頂点）と道路（辺）

### 無向グラフとは？

辺に **方向がない** グラフです。「A と B がつながっている」＝「B と A もつながっている」。

```
  無向グラフ（本プロジェクトで扱う形式）：
    A ── B    （A→B も B→A も OK）

  有向グラフ（参考）：
    A ──→ B   （A→B だけ。B→A は別の辺が必要）
```

> 💡 本プロジェクトのデータはすべて **無向グラフ** として扱います。
> 元が有向グラフの場合も、前処理で無向グラフに変換されています。

### 疎（スパース）グラフ vs 密（デンス）グラフ

- **疎（スパース）グラフ**：各頂点のつながりが少ない。辺の数がノード数に比べて少ない。
  - 例：道路ネットワーク（各交差点からは 2〜4 本の道路しか出ていない）
- **密（デンス）グラフ**：各頂点のつながりが多い。辺の数がノード数に比べて非常に多い。
  - 例：SNS（人気のある人は数千人のフォロワーを持つ）

> 💡 本プロジェクトで使うグラフはほぼすべて **疎（スパース）グラフ** です。
> だからこそ、メモリを節約できる **CSR 形式** が適しています。

### Betweenness Centrality（媒介中心性）とは？

「このノード（人・場所）は、ネットワーク全体でどれくらい **仲介役** として重要か？」を測る指標です。

```
  A ── B ── C ── D
       |
       E

  B と C の BC 値は高い（多くの最短経路が通る）
  A, D, E の BC 値は低い（端にいるので仲介しない）
```

BC が高いノードは、ネットワークの **ボトルネック** や **重要拠点** です。
例えば道路ネットワークなら「ここが渋滞すると全体が止まる交差点」を見つけられます。

## CSR ファイル形式

各ファイルはちょうど **3 行** で構成されます：

```
Line 1:  n_nodes  n_edges
Line 2:  ptr[0]  ptr[1]  ...  ptr[n_nodes]       (n_nodes + 1 個の行ポインタ)
Line 3:  adj[0]  adj[1]  ...  adj[2*n_edges - 1]  (隣接リスト、両方向)
```

### なぜ CSR 形式を使うのか？

グラフをプログラムで表現する方法はいくつかあります。代表的な 3 つを比較します：

| 表現方法 | メモリ使用量 | GPU との相性 | 特徴 |
|---------|------------|-----------|------|
| **隣接行列**（2 次元配列） | ノード数² に比例 | △ | 密グラフ向き。疎グラフでは 99% 以上が 0 でメモリの無駄 |
| **隣接リスト**（各ノードにリスト） | 辺数に比例 | ✗ | ポインタが散在し、GPU のメモリアクセスが遅くなる |
| **CSR**（圧縮行形式） | 辺数に比例 | ◎ | 2 本の配列だけで表現。GPU が連続メモリをまとめて読める |

> 💡 **CSR は「疎グラフを、GPU が高速に処理できる形で、省メモリに格納する」ための形式です。**

### CSR の読み方

頂点 `v` の隣接頂点は、`adj` 配列の `ptr[v]` から `ptr[v+1] - 1` の位置に格納されています。

**例** — 5 頂点・5 辺の無向グラフ：

```
■ ステップ 1：グラフの形を確認する

    0 ── 1 ── 3
    |    |
    2    4

  辺のリスト：0-1, 0-2, 1-3, 1-4, 2-1（← 手で数えて 5 本）

■ ステップ 2：CSR ファイルの中身を見る

    5 5                         ← 5 nodes, 5 edges
    0 2 5 7 9 10                ← ptr 配列（行ポインタ）：6 個の値（5 ノード + 1）
    1 2 0 3 4 0 1 1 3           ← adj 配列（隣接リスト）：10 個の値（5 辺 × 2 方向）

■ ステップ 3：各頂点の隣接頂点を読み取る

  ptr 配列:  [0, 2, 5, 7, 9, 10]
  adj 配列:  [1, 2, 0, 3, 4, 0, 1, 1, 3, ─]
              ↑     ↑        ↑     ↑     ↑
              |     |        |     |     └── ptr[4]=9 ここから
              |     |        |     └──────── ptr[3]=7 ここから
              |     |        └────────────── ptr[2]=5 ここから
              |     └─────────────────────── ptr[1]=2 ここから
              └───────────────────────────── ptr[0]=0 ここから

  ┌──────────┬────────────────────────────────────────────────┬───────────┐
  │ 頂点     │ 読み方                                         │ 隣接頂点   │
  ├──────────┼────────────────────────────────────────────────┼───────────┤
  │ 頂点 0   │ adj[ptr[0] .. ptr[1]-1] = adj[0..1]           │ → {1, 2}  │
  │ 頂点 1   │ adj[ptr[1] .. ptr[2]-1] = adj[2..4]           │ → {0, 3, 4}│
  │ 頂点 2   │ adj[ptr[2] .. ptr[3]-1] = adj[5..6]           │ → {0, 1}  │
  │ 頂点 3   │ adj[ptr[3] .. ptr[4]-1] = adj[7..8]           │ → {1, 3}  │
  │ 頂点 4   │ adj[ptr[4] .. ptr[5]-1] = adj[9..9]           │ → {3}     │
  └──────────┴────────────────────────────────────────────────┴───────────┘

  確認：頂点 0 の隣を見ると {1, 2}。グラフの図で 0 は 1 と 2 につながっている → ✅ 正しい！
```

> ⚠️ **辺数についての注意**: グラフは無向グラフのため、各辺は両方向に格納されます。
> 例えば辺 0-1 は、adj に「頂点 0 の隣に 1」と「頂点 1 の隣に 0」の 2 回現れます。
> そのため `adj` 配列のエントリ数は `2 × n_edges` になります。

## グラフ特性と BC への影響

グラフにはさまざまな構造的特性があり、それが BC の計算時間や結果の傾向に影響します。

| 特性 | かんたんな説明 | 代表グラフ | BC 計算への影響 |
|-----|-------------|-----------|--------------|
| **Scale-free**（スケールフリー） | 少数の「超人気ノード」（ハブ）に辺が集中する構造。SNS で言えば、フォロワーが数万人いるインフルエンサーのような存在。 | amazon*, web-* | BC 値が少数のハブノードに集中する。ハブを経由する最短経路が非常に多いため。 |
| **疎・均一次数**（道路型） | すべてのノードのつながり数がほぼ同じ（道路の交差点は大体 2〜4 本）。特別な「ハブ」がない。 | roadNet-* | BFS（幅優先探索）の探索が深くなりやすく、計算の「後退フェーズ」が長くなる。GPU の並列性が活かしにくい。 |
| **高密度**（ソーシャル型） | ノード 1 つあたりのつながり数が非常に多い。辺の総数がノード数に比べて桁違いに大きい。 | soc-Pokec, as-skitter | 各 BFS レベルで処理する辺が膨大になり、後退フェーズの計算量が実行時間全体を支配する。 |

> 💡 **道路ネットワーク（roadNet-*）はノード数の割に辺が少なく、Web グラフは辺が多い。**
> 同じノード数でも、グラフの種類によって計算時間が大きく変わります。

## 📚 用語集（Glossary）

初めて目にする用語があれば、ここで確認してください。

| 用語 | 英語 | 意味 |
|-----|------|------|
| **頂点（ノード）** | Vertex / Node | グラフ上の「点」。人、場所、Web ページなど。 |
| **辺（エッジ）** | Edge | 2 つの頂点を結ぶ「線」。つながりや関係を表す。 |
| **無向グラフ** | Undirected Graph | 辺に方向がないグラフ。A-B と B-A を区別しない。 |
| **有向グラフ** | Directed Graph | 辺に方向があるグラフ。A→B と B→A は別の辺。 |
| **疎（スパース）** | Sparse | 辺の数がノード数に比べて少ないこと。 |
| **密（デンス）** | Dense | 辺の数がノード数に比べて非常に多いこと。 |
| **CSR** | Compressed Sparse Row | 疎グラフを 2 本の配列で表現する省メモリ形式。 |
| **BFS** | Breadth-First Search | 幅優先探索。近いノードから順に探索するアルゴリズム。 |
| **BC（媒介中心性）** | Betweenness Centrality | ノードが最短経路の「仲介役」として登場する頻度の指標。 |
| **Scale-free** | Scale-free network | 少数のハブノードが大量の辺を持つネットワーク構造。 |
| **Sequential** | Sequential execution | 1 つの CPU コアで順番に処理する実行方式。 |
| **OpenMP** | Open Multi-Processing | 複数の CPU コアで並列処理するための仕組み。 |
| **GPU** | Graphics Processing Unit | 大量の小さな計算を同時に行える装置。元は画像処理用だが、グラフ計算にも使える。 |
| **SNAP** | Stanford Network Analysis Project | スタンフォード大学が公開している実世界グラフのデータ集。 |
